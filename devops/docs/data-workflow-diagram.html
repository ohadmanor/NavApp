NavApp — Data Files Workflow (Online & Offline)

How each dataset in data/ is hosted, streamed online, cached/stored offline, and deployed across Web PWA, Android/iOS, and DevOps scripts.

1. Resolution Priority on App Startup (All Runtime Files)

1. Android Native Storage filesDir/maps/{file}
Shared by WebView & Android Auto (zero network).
→
2. Browser OPFS maps/{file}
Full local copy on Web when downloaded for offline use.
→
3. Local Dev Server /data/{file}
On localhost only (Vite HTTP 206 middleware).
→
4. Cloud Origin + Cache Firebase Storage (DEM) or Firebase Hosting hosting:data, backed by Cache API & IndexedDB.

2. Per-File Online & Offline Workflow

Israel.dem.pmtiles Firebase Storage · 1.31 GiB
Immutable Terrarium 256px PNG elevation pyramid (z0–z14). Powers Hillshade, 3D Terrain, 10m/50m Contours (maplibre-contour), and ElevationService.
Online Mode Streamed via VITE_DEM_PMTILES_URL from Firebase Storage (map_data/Israel.dem.pmtiles) using HTTP 206 Partial Content byte-range requests + CORS. CachedFetchSource (pmtiles-range-cache-v3, immutable: true) caches every fetched range on disk with an 8s timeout.
Offline Mode
  • Partial offline: Previously viewed tiles & headers load from pmtiles-range-cache-v3 with zero revalidation.
  • Full offline: User downloads full archive in Offline Maps into OPFS (Web) or filesDir/maps/ (Android).
DevOps Excluded from hosting:data (too large for Hosting CDN). Upload to Firebase Storage bucket map_data/; download-map-data.bat pulls from Storage.
Israel.osm.pmtiles Hosting Data · ~110 MB
Updatable OpenMapTiles 19-layer vector archive (z0–z14) with trail colors. Powers base map, roads, trails, water, and runtime search rebuilds.
Online Mode Streamed via HTTP 206 from navapp-israel-topo-data.web.app/data/Israel.osm.pmtiles. CachedFetchSource revalidates header (offset=0) when online and clears range cache automatically if ETag changes.
Offline Mode Stored in OPFS or Android filesDir/maps/ via Offline Maps. On startup when online, checks size/ETag in background and hot-swaps if updated.
DevOps Uploaded to hosting:data via devops/upload-map-data.bat.
Israel.pois.geojson Hosting Data · ~27 MB (3 MB gz)
68,965 POIs (6,732 OSM + 62,233 Off-Road community POIs). Hydrated by PoiManager.initializePois() with periodic event-loop yields.
Online Mode Fetched gzipped from navapp-israel-topo-data.web.app/data/Israel.pois.geojson (Service Worker navapp-offline-v13 uses network-first with cache fallback). Saved to OPFS/Native + OSM POIs synced into IndexedDB (db.pois).
Offline Mode Loads from OPFS / Native storage (or Service Worker cache if OPFS unavailable), falling back to IndexedDB db.pois. Background ETag/size check updates silently when online.
DevOps Uploaded to hosting:data via devops/upload-map-data.bat.
Israel.search.idx Hosting Data · ~1.7 MB
Pre-built gzipped full-map search index (cities, peaks, rivers, 4x4 tracks, highways) paired with Israel.osm.pmtiles fingerprint.
Online Mode Lazy-loaded when search bar is focused or 4s after map ready. Fetched from navapp-israel-topo-data.web.app/data/Israel.search.idx (network-first in SW) and saved to OPFS/Native.
Offline Mode Loads from OPFS / Native storage (or SW cache / IndexedDB searchIndexCache). If user imports a custom local .pmtiles, rebuilds in-browser and caches in IndexedDB.
DevOps Auto-rebuilt by upload-map-data.mjs when Israel.osm.pmtiles is newer, then deployed to hosting:data.
Israel.trails.json Pipeline / Enrichment · ~818 KB
Trail enrichment directory used by the PBF → PMTiles build pipeline and trail annotation tooling.
Online / Hosting Deployed to hosting:data alongside OSM/POIs/Search via upload-map-data.bat. Not fetched during normal map boot.
Offline / Pipeline Synced to local data/ via download-map-data.bat for offline Tilemaker builds.
App Shell (dist/ + sw.js) Hosting App · navapp-israel-topo.web.app
Code-split Vite PWA (index, maplibre, firebase, vendor, lazy modals/drawers) + Service Worker navapp-offline-v13.
Online Mode sw.js pre-caches icons, sprites, POI SVGs, and RTL plugin on install, and caches visited JS/CSS chunks. Range requests & cross-origin Storage/tile requests bypass SW.
Offline Mode All app shell assets, glyphs (offline-glyphs://), sprites, and chunks load from navapp-offline-v13 cache. User routes/POIs/drafts persist in IndexedDB (NavAppOutdoorDB).
